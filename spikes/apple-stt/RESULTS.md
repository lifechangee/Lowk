# Apple on-device STT (SpeechAnalyzer / DictationTranscriber / SFSpeechRecognizer) для Lowk

Дата: 2026-10-21. Mac: M4, macOS 27.0.1 (build 26A434), Xcode 27.1, Swift 6.4. Те же 20 записей владельца, что и в `spikes/stt-bench` (01-05 x me/them x quiet/noisy), подача в реальном времени чанками по 160 мс, метрики считаются тем же кодом (`stt-bench/harness/common.py`: нормализация, WER/CER через jiwer, оценка конца слова по Silero VAD, English terms).

## Вывод (коротко)

**Не заменять и пока не добавлять.** Apple не умеет главное для Lowk: один транскрайбер = одна локаль, смешанный RU+EN (code-switching) не поддерживается, а русский есть только в старой модели `DictationTranscriber` (SpeechTranscriber нового поколения русский не поддерживает). Качество на наших записях хуже всех конкурентов (WER 0.40 против 0.23-0.31), английские термины латиницей сохраняются в 16-23% случаев, финализация текста приходит с задержкой около 6 с. Плюсы реальны (почти нулевая нагрузка, лицензия бесплатная, ничего не качаем с наших серверов), но не перевешивают. Возможная роль в будущем: запасной «лёгкий» движок для одноязычных (только RU или только EN) созвонов на Mac; приоритет низкий. На Windows аналога нет, значит всё равно нужен общий движок.

## 1. Что умеют API (исследование)

| вопрос | ответ | источник |
|---|---|---|
| API | `SpeechAnalyzer` + модули `SpeechTranscriber` (новая модель), `DictationTranscriber` (старая диктовка: «те же языки, модель и устройства, что on-device SFSpeechRecognizer из iOS 10»). Всё on-device, модели «скачиваются», хранятся системой вне памяти приложения. | WWDC25 сессия 277 https://developer.apple.com/videos/play/wwdc2025/277/ ; docs https://developer.apple.com/documentation/speech/speechtranscriber , https://developer.apple.com/documentation/speech/dictationtranscriber |
| Русский | **SpeechTranscriber: нет** (45 локалей на этом Mac: en/de/es/fr/it/pt/ja/ko/zh/yue + индийские; ru нет). **DictationTranscriber: ru_RU есть** (54 локали). **SFSpeechRecognizer: ru-RU on-device есть.** Проверено `applestt probe` на этом Mac. Apple не публикует список в статьях, надёжно только `supportedLocales` в рантайме. | замер, см. `applestt probe` |
| Несколько языков / code-switching | Нет. Транскрайбер создаётся с одной `Locale`, автоопределения языка и смешивания нет. Единственный обходной путь: по одному анализатору на локаль и выбор по уверенности (сторонний пример swift-speech-lanes), это не настоящее смешивание внутри фразы. Также есть лимит числа одновременно выделенных языковых ассетов (WWDC25: при превышении надо вызвать `AssetInventory` deallocate). | WWDC25/277; https://github.com/ivan-magda/swift-speech-lanes |
| Стриминг | `reportingOptions: [.volatileResults]`: volatile = быстрые черновые догадки, менее точные; finalized = окончательные, по диапазону аудио больше не меняются. Без опции приходят только финальные. | WWDC25/277 |
| Задержка | Apple цифр не даёт («быстрее старой модели»). Наши замеры ниже. | замер |
| Параллельные потоки | API асинхронный, анализаторов можно создавать несколько. Мы проверили 2 и 4 потока одновременно (ниже): деградации нет. | WWDC25/277; замер |
| Ассеты | `AssetInventory.status/assetInstallationRequest/downloadAndInstall`; скачивание по требованию с `Progress`; обновляет система. На практике: `ru_RU` для Dictation и `en_US` для Speech скачались при первом запуске. | WWDC25/277; замер |
| Лицензия | Бесплатно, без поминутной оплаты, для сторонних приложений (Apple прямо позиционирует как «как в Notes»). Отдельных условий для Speech framework, кроме стандартного Apple Developer Program License / SDK, не нашёл; юридически не проверял, перед релизом сверить. SFSpeechRecognizer требует разрешение пользователя (TCC) и строку `NSSpeechRecognitionUsageDescription`. | WWDC25/277 |
| Windows | Аналога нет. API только Apple-платформы. На Windows нужен собственный движок (в любом случае). | |

## 2. Замеры

CLI: `Sources/applestt/main.swift` (`swift build -c release`, затем `applestt run <audio> --engine speech|dictation|sfs --locale ru-RU`), оценка: `score.py`, прогон: `run_ru.sh`. Сырые оценённые результаты: `results/*.json`.

Что измерено:
- **DictationTranscriber ru_RU**, все 20 записей, `volatileResults + frequentFinalization`.
- **SpeechTranscriber en_US и DictationTranscriber en_US** только на 05 (в этом ru нет вообще). Важно: 05 содержит и русские вставки, модель en_US их портит, поэтому WER 05 для en-моделей завышен.
- **SFSpeechRecognizer ru-RU on-device: НЕ ИЗМЕРЕН.** CLI-процесс завис на запросе разрешения Speech Recognition (TCC, статус notDetermined), выдать его без UI нельзя. По WWDC25 DictationTranscriber = та же модель, поэтому результаты показательны и для него.
- SpeechTranscriber для русского: нет модели, мерить нечего.

Подготовка для сравнимости: колонка «задержка слова» считается тем же способом, что в stt-bench (момент первого появления слова в потоке минус оценка конца слова), но здесь агрегируем слова всех клипов набора вместе, p50/p95. Оценка конца слов приблизительна (+-0.3 с). Позиционное сопоставление слов штрафует движки, которые переписывают черновик (у Apple p95 volatile получается 8-13 с, отчасти артефакт метода).

Дополнительно по Apple:
- Задержка первого слова после начала речи (onset -> первый partial) p50 **0.72 с** (ru), 0.85 с на 05.
- **Финализация приходит блоками**: слова становятся «окончательными» в среднем через 6-7 с после произнесения (p95 около 20 с), хотя `frequentFinalization` включён. Черновик (volatile) быстрее, но он правится.
- 05 EN-heavy, en_US модели: SpeechTranscriber WER 0.44, EN-термины латиницей 81%, задержка слова p50 2.2 с, первый partial 2.0 с; DictationTranscriber en_US WER 0.39, термины 77%, p50 0.5 с. Модель русские вставки не понимает.
- Примеры русской модели: «latency» -> «Лейси», «деплой» -> «диплом», «API» -> «AP», «retention D30» -> «Retention до 30».
- Нагрузка: CPU RTF 0.005-0.009, RSS процесса около 25 MB (сама модель живёт в системном процессе).
- **Два и четыре параллельных потока** (me/them одновременно, потом 4): WER 0.39-0.40, задержка и нагрузка такие же, как у одиночного потока (одиночные те же клипы: WER 0.396). Параллельность не проблема.

## 3. Рекомендация

1. **Skip как основной движок.** Для Lowk ключевое сочетание «RU+EN в одной фразе, <1 с, два потока» Apple не закрывает: нет code-switching, русский только в старой модели, WER 0.40 против 0.23-0.31, термины хуже Whisper/Deepgram в 3 раза, финалы с задержкой около 6 с, macOS-only.
2. Оставить в виду как опцию «lite» для Mac (ноль установки модели от нас, 25 MB, ничтожный CPU) для одноязычных созвонов; делать только если появится запрос, после основного пайплайна.
3. Повторить замер, когда Apple добавит ru в SpeechTranscriber (проверка одной командой `applestt probe`) и если когда-нибудь появится мульти-язык.
4. Не измерено: SFSpeechRecognizer (нужно разрешение TCC через GUI), `.mul_IN` мультиязычная локаль не пробовалась (индийские языки), тест на живом микрофонном/системном аудио, латентность при нагрузке другими агентами.
