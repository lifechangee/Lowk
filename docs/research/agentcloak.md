# AgentCloak Desktop: исследование и план отдельного модуля

Дата исследования: 2026-10-20.

## 1. Что такое AgentCloak Desktop и как это работает

**Продукт.** AgentCloak Desktop - бесплатный инструмент от InCountry для защиты персональных данных при работе с AI-чатами. Он заменяет чувствительные значения в промпте синтетическими подстановками до отправки в модель, а в ответе возвращает настоящие значения локально на устройстве.

**Как работает (по данным вендора):**
- **Детекция локально.** Очистка (cloaking) выполняется на компьютере пользователя; вендор называет компактную модель *Rampart* и говорит о сочетании фиксированных правил и нейросетевой детекции.
- **Маппинг ("digital twins").** Хранится соответствие реальное значение - подстановка. Вендор утверждает, что это соответствие не уходит в AI.
- **Восстановление.** В ответе модели подстановки заменяются обратно на реальные значения.
- **Функция "Remember".** Сохраняет пары реальное-подстановка на компьютере, чтобы не подтверждать очистку каждый раз.

**Что не подтверждено.** Связь между AgentCloak и Rampart из открытых источников не подтверждена: поиск не нашел документа, который бы связывал их явно. Отдельный Rampart от National Design Studio существует (ONNX, ~14.7 MB, MiniLM-L6, 17 типов сущностей, 7 языков), но его использование в AgentCloak не доказано. Вендор не раскрывает, куда именно хранятся маппинги, шифруются ли они, и отправляется ли что-либо на серверы для Desktop-версии. Эти пункты надо проверять на практике, например через DevTools и анализ трафика service worker, как советует сам вендор.

**Целевая аудитория.** Частные пользователи AI-чатов. Для организаций вендор направляет к серверному продукту AgentCloak Server.

**Цены и лицензия.**
- Desktop и браузерные расширения: бесплатно для личного использования. Лицензия продукта закрытая, это не open source.
- AgentCloak Server: коммерческий продукт, цены публично не указаны (нужна заявка на демо).

## 2. Ключевые возможности

- Детекция и подмена: имена, email, телефоны, URL, SSN и ИНН, банковские реквизиты и номера счетов, адреса.
- Категории очистки: имя, возраст, локация, медицинские термины, пол, вес, финансовые данные. Для каждой категории свой режим (подмена, обобщение, маска, оставить как есть).
- Языки (Desktop, заявлено): английский, испанский, французский, немецкий, итальянский, португальский, нидерландский. Русского в списке нет.
- Платформы: браузеры Chrome, Edge, Safari; чаты ChatGPT, Claude, Gemini, Cowork, Grok, DeepSeek, Copilot (страница противоречива); desktop-приложение пока только ChatGPT Desktop; macOS и Windows.
- Серверная версия (платная): более сильные модели, очистка загружаемых файлов, группировка digital twins, MCP-прокси для Salesforce/HubSpot, аудит-логи, SSO (Entra, Okta, Google), развертывание on-prem и air-gapped.
- Отзывов независимых пользователей не найдено; источники - в основном пресс-релизы вендора.

## 3. Как сделать похожий отдельный модуль

### Архитектура

Модуль - независимый сервис/библиотека без привязки к Lowk. Lowk подключает его как зависимость или внешний процесс.

1. **Детекция (многоступенчатая, локально).**
   - Слой 1, правила и валидаторы: regex + контрольные суммы (Luhn для карт, IBAN mod-97, ИНН/СНИЛС/ОГРН с контрольными разрядами, email, телефоны, API-ключи по префиксам и энтропии для секретов).
   - Слой 2, NER: локальные модели для имен, адресов, организаций. Варианты: GLiNER (zero-shot, любые типы сущностей), Presidio как оркестратор, для русского - Natasha/Slovnet (NER на CPU).
   - Слой 3 (опционально): LLM-проверка на сложных случаях, но только локально.
2. **Pseudonymization vault.** Обратимое сопоставление "реальное - токен" с шифрованием at-rest (например, XChaCha20-Poly1305 с ключом из ОС keychain), привязкой к сессии, сроком жизни и возможностью явного стирания. Подстановки должны сохранять формат (тип, длину, структуру), чтобы LLM не ломалась.
3. **Streaming re-identification.** Ответ LLM приходит по токенам, поэтому токен может разрезаться на границе чанков. Нужен буфер, который держит хвост, пока не станет ясно, что это не начало подстановки.
4. **Изображения и скриншоты.** OCR (Tesseract, Apache-2.0, или Presidio Image Redactor) -> детекция по тексту -> закрашивание bbox. Важно: OCR на уровне bbox, не только текста.
5. **Интерфейсы.**
   - Rust-крейт (ядро) с C-ABI для встраивания в Tauri/Lowk.
   - CLI для скриптов.
   - Локальный HTTP-прокси, совместимый с OpenAI API: любое приложение меняет base URL, модуль очищает запрос и восстанавливает ответ. Это самый переиспользуемый вариант.

### Открытые building blocks и лицензии (проверено, если не указано иное)

| Компонент | Лицензия | Комментарий |
|---|---|---|
| Microsoft Presidio | MIT | Проект ушел из Microsoft в community-организацию data-privacy-stack. Детекция английская по умолчанию, для других языков нужны модели и свои recognizers. Python. |
| GLiNER (код) | Apache-2.0 (по агрегатору, сверить с LICENSE) | Веса зависят от чекпоинта: gliner_*-v2.1 и pii-v1 - Apache-2.0; более ранние base/small/medium v1 - CC-BY-NC-4.0 (несовместимо с коммерцией). |
| Natasha / Slovnet (русский NER) | MIT (по пакетным индексам) | Веса нужно проверить отдельно на репозитории natasha/slovnet. Обучены в основном на новостях. |
| Rampart (National Design Studio) | не проверено | Лицензию весов нужно проверить до использования. |

Совместимость с AGPL: MIT и Apache-2.0 совместимы. CC-BY-NC-модели несовместимы с коммерческим использованием.

### Язык реализации

Rust предпочтителен: единый стек с Lowk (Tauri 2), производительность, C-ABI. Минусы: NER-модели в Rust требуют ONNX Runtime (крейт `ort`) и токенизаторов Hugging Face. Presidio и GLiNER - Python, их можно вызывать как отдельный sidecar-процесс с HTTP. Оптимальный вариант на старте: ядро на Rust (правила, валидаторы, vault, streaming-буфер) + ONNX-модели (GLiNER, Slovnet через конвертацию), плюс HTTP-прокси.

## 4. Оценка трудоемкости и риски

**Оценка (один опытный разработчик, без ресерча моделей):**
- Правила и валидаторы, RU+EN: 1-2 недели.
- Vault, шифрование, streaming re-identification, OpenAI-совместимый прокси: 2-3 недели.
- NER через ONNX (GLiNER/Slovnet), интеграция и бенчмарк на русских и английских данных: 3-4 недели.
- OCR-редакция скриншотов: 1-2 недели.
- Итого MVP: около 2-3 месяцев; качественный продукт с тестами на собственном датасете: 4-6 месяцев.

**Риски:**
- Качество детекции: NER пропускает сущности; нужен размеченный датасет RU/EN, который придется собрать самим.
- Лицензии весов моделей (см. таблицу), особенно CC-BY-NC.
- Утечки через сам LLM: модель может восстановить имя по контексту даже после подстановки. Нужна проверка, а не только маскировка.
- Потеря маппинга = потеря возможности восстановить ответ. Нужна политика хранения.
- Ложная уверенность: очистка не гарантирует соответствие 152-ФЗ или GDPR; это надо декларировать честно.
- Конкуренция: AgentCloak бесплатен для личного использования, поэтому сильная ниша - открытый, локальный, переиспользуемый модуль для разработчиков, а не конечный продукт для пользователя.

## Итог

AgentCloak Desktop - закрытый бесплатный клиент с локальной очисткой и восстановлением, где ключевые детали (модель, хранилище маппингов, отправка данных) не раскрыты. Отдельный open-source модуль на Rust с ONNX-моделями, правилами с контрольными суммами и OpenAI-совместимым прокси реализуем за 2-3 месяца MVP. Перед стартом проверить лицензии весов моделей и собрать RU/EN датасет для замеров.
