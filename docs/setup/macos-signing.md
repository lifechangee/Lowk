# Подпись Lowk на macOS: один раз создать сертификат «Lowk Dev»

Зачем. macOS запоминает разрешения (микрофон, запись экрана, мониторинг ввода, универсальный доступ)
по подписи приложения. Если подпись каждый раз новая, выданные разрешения «теряются» после пересборки и
статус в Lowk остаётся «не выдано». Свой сертификат делает подпись постоянной.

## Создать сертификат (2 минуты, один раз)

1. Откройте **Связку ключей** (Keychain Access).
2. В строке меню: **Связка ключей → Ассистент сертификации → Создать сертификат…**
3. Имя: `Lowk Dev`. Тип удостоверения: **Самоподписанный корневой**. Тип сертификата: **Подпись кода** (Code Signing).
4. Нажмите **Создать**, затем **Готово**. Сертификат появится в связке «Вход» (login).
5. Проверка в Терминале:

       security find-identity -v -p codesigning

   В списке должна быть строка с `"Lowk Dev"`.

## Собрать приложение с этой подписью

    LOWK_SIGN_IDENTITY="Lowk Dev" just build

Без переменной сборка всё равно работает: подпись «ad-hoc», но с идентификатором `dev.lowk.app`
(как у приложения) и привязкой к нему. Сертификат надёжнее: рекомендуем использовать его.

При первой подписи macOS может спросить доступ к ключу: нажмите «Всегда разрешать».

## После первой сборки с новой подписью

Старые записи Lowk в «Системные настройки → Конфиденциальность и безопасность» относятся к прежней подписи.
Удалите их кнопкой «−» (микрофон, запись экрана, мониторинг ввода, универсальный доступ), запустите новый
`Lowk.app` и выдайте разрешения заново в онбординге. После этого пересборки с тем же сертификатом разрешения
не сбрасывают.

Если статус «Запись экрана», «Мониторинг ввода» или «Универсальный доступ» не стал «выдано» сразу после
включения переключателя, это нормально: macOS применяет их только к заново запущенному приложению. Lowk
покажет «Перезапустите Lowk, чтобы применить» и кнопку перезапуска.

Проверка подписи: `just qa-bundle` (идентификатор подписи должен совпасть с `dev.lowk.app`).
