# Автоопределение звонка: «Начать запись?»

Статус: ресёрч + дизайн (2026-10-22). Прототип: `spikes/call-detect/main.swift` (macOS, Swift, ~60 строк).
Связано: BRIEF «автодетект созвона — роадмап», ARCHITECTURE (lowk-audio: `list_processes`, `list_sources`; lowk-platform: perm).

## 1. Принцип

Звонок = «приложение-кандидат держит микрофон» (главный сигнал) + подтверждения (выходной звук того же приложения, камера, заголовок окна — опционально). Ничего не читаем из содержимого окон, не делаем скриншотов, не слушаем аудио. Опрос раз в 1–2 с (или слушатели свойств) — CPU ≈ 0.

## 2. Сигналы

### macOS (14.4+, те же API, что у тапа в lowk-audio)

| Сигнал | API | Права | Надёжность | Заметки |
|---|---|---|---|---|
| Процесс использует микрофон | `kAudioHardwarePropertyProcessObjectList` + `kAudioProcessPropertyIsRunningInput`, `PID`, `BundleID` | не нужны | Высокая | Проверено в спайке: переход +/- виден за <1 с, звук не нужен. У CLI-процессов bundle пуст — группируем по .app через существующий `groups()`. Хелперы (Chrome Helper, WebKit.GPU) уже сводятся к владельцу в `procs.rs` |
| Процесс выводит звук | `kAudioProcessPropertyIsRunningOutput` | не нужны | Средняя | Бывает и у музыки/видео; только как подтверждение (mic + out одного приложения) |
| Камера включена | CoreMediaIO `kCMIODevicePropertyDeviceIsRunningSomewhere` | не нужны | Средняя | Не говорит, КАКОЕ приложение; звонки без видео не видны. Подтверждение, не триггер |
| Оранжевый индикатор микрофона / TCC | нет публичного API | — | — | Не использовать |
| Заголовок окна (Meet «Meet –», Zoom «Zoom Meeting») | `CGWindowListCopyWindowInfo` (имена окон других процессов требуют Screen Recording), либо AX | Screen Recording / Accessibility | Средняя | Нужен только чтобы отличить вкладку Meet от других вкладок Chrome и название созвона. Опционально, по умолчанию выключено |
| Сеть (UDP/STUN) | — | — | Низкая | Отвергнуто: хрупко, навязчиво |

Браузеры: микрофон держит процесс Chrome/Arc/Edge/Safari (WebKit.GPU/Chrome Helper), не вкладка. Сам по себе сигнал говорит «в браузере кто-то слушает», а не «это Meet». Различение: (а) заголовок окна/вкладки (AX или Screen Recording), (б) AppleScript/Chrome-расширение (слишком тяжело, отвергнуто), (в) без различения: показываем «Chrome использует микрофон — записать?». Для альфы выбран (в), заголовок — опциональное улучшение WP-4.

### Windows 10/11

| Сигнал | API | Права | Надёжность | Заметки |
|---|---|---|---|---|
| Сессии захвата на микрофоне | WASAPI `IAudioSessionManager2` по capture-эндпоинту, `IAudioSessionControl2::GetProcessId`, состояние Active + `RegisterSessionNotification` | не нужны | Высокая | Событийно, без опроса. `win.rs` уже перечисляет сессии (render) — добавить capture-эндпоинт |
| Последнее использование микрофона | реестр `HKCU\...\CapabilityAccessManager\ConsentStore\microphone\<app>` : `LastUsedTimeStart` / `LastUsedTimeStop` (Stop=0 → сейчас используется); для не-упакованных — подключ `NonPackaged` | не нужны | Высокая, это источник значка микрофона в трее Windows | Резерв/кросс-проверка; даёт путь exe. Опрос реестра дешёвый |
| Вывод звука приложения | render-сессии (peak meter `IAudioMeterInformation`) | нет | Средняя | Подтверждение |
| Камера | ConsentStore `webcam` | нет | Средняя | Подтверждение |
| Заголовок окна | `GetWindowText` / UIA | нет прав | Средняя | На Windows доступнее, чем на macOS; те же ограничения по приватности |

### Приложения

| Приложение | Идентификация | Триггер | Конец | Риски ложных |
|---|---|---|---|---|
| Zoom | `us.zoom.xos` / `Zoom.exe` | mic Y (процесс zoom.us) | mic N 5 с | Zoom держит mic только в звонке — надёжно |
| Teams | `com.microsoft.teams2` / `ms-teams.exe` | mic Y | mic N | Хорошо; Teams может держать mic при предпросмотре устройств |
| Google Meet | Chrome/Arc/Edge/Safari | mic Y браузера (+ заголовок «Meet –») | mic N | Любой сайт с микрофоном (Discord web, голосовые заметки) |
| Discord | `com.hnc.Discord` / `Discord.exe` | mic Y | mic N | Режим «вкл. микрофон» в голосовом канале может быть без звонка 1:1 — принимаем |
| Telegram | `ru.keepcoder.Telegram` / `Telegram.exe` | mic Y | mic N | Голосовые сообщения (запись ГС) — ложные: короткие, отсекаются debounce |
| Slack huddle | `com.tinyspeck.slackmacgap` / `slack.exe` | mic Y | mic N | Huddle держит mic только в хадлле |
| FaceTime | `com.apple.FaceTime` (macOS) | mic Y | mic N | Windows нет |
| WhatsApp / Signal / Webex | список расширяемый | mic Y | | |

Вывод: универсальный триггер «mic Y у приложения из списка» покрывает всё; список приложений — это только allow-list и UI-названия.

## 3. Машина состояний

```
Idle ──(mic Y у приложения из списка)──▶ Candidate(app, t0)
Candidate ──(держится ≥ 5 с непрерывно)──▶ Detected  → показать пилюлю (если не запись и не mute-app)
Candidate ──(пропал < 5 с)──▶ Idle                      (ГС Telegram, диктовка)
Detected ──(пользователь: Записать / авто-старт)──▶ Recording(app)
Detected ──(Не сейчас / игнор 20 с)──▶ Dismissed(app, до конца этой сессии mic)
Recording ──(mic N у app ≥ 8 с, gap-hold)──▶ Ended → «Звонок завершён. Остановить и сделать саммари?»
Ended ──(нет ответа 60 с)──▶ автоостановка выключена по умолчанию; пилюля остаётся
```

Правила:
- Debounce старта 5 с (настраиваемо 3–10); дебаунс конца 8 с (переподключения, mute/unmute у Meet и Teams могут отпускать устройство).
- Слабые источники отсекаются по профилю: Apple Dictation (`com.apple.speech*`, `corespeechd`), Siri, «Диктофон»/Voice Memos, Lowk сам (по своему pid), записывающие утилиты, браузер без Meet-заголовка при включённой опции «только Meet». Системные демоны в мусорный deny-list по bundle id.
- Диктовка/голосовая заметка обычно <5 с или не из allow-list — режется сразу; Voice Memos в deny-list.
- Если запись уже идёт (любым способом) — пилюля не показывается; конец звонка предлагается только для записи, начатой по приглашению или привязанной к app.
- Dismissed: не повторять, пока mic этого приложения не отпускался ≥ 30 с. «Больше не предлагать для X» — в настройки.
- Несколько приложений: берём то, чей mic держится дольше; остальные в подпись.

## 4. UX

- Пилюля (не модальная, не крадёт фокус): «Zoom — идёт звонок. [Записать] [×]», в стелс-логике не появляется в оверлее/демонстрации экрана при активном шеринге? Решение: показывать системным уведомлением (macOS UserNotifications, Windows toast) с кнопкой — оно по природе видно на демонстрации; поэтому опция «тихий режим»: только значок в трее/menu bar без всплывающего окна, чтобы не светить на шеринге. По умолчанию — тихий значок + уведомление выключено, пока пользователь не включил (согласуется со стелс-позиционированием продукта).
- Клик по «Записать»: старт `lowk-session` с источником = это приложение (+ микрофон), папка по умолчанию.
- Конец: «Звонок завершён (Zoom, 42 мин). [Остановить и саммари] [Продолжить]».
- Предупреждение о законности записи (BRIEF) показывается при первом включении автостарта; автостарт — с явным согласием пользователя.

## 5. Настройки

`detect.enabled` (выкл. по умолчанию в альфе, вкл. после онбординга), список приложений с режимом на каждое: «спрашивать» / «писать автоматически» / «игнорировать»; `detect.debounce_start_s`, `detect.debounce_end_s`; «предлагать остановку при завершении»; `detect.window_titles` (выкл.); `detect.notify_mode` (тихий значок / уведомление); «папка по умолчанию для автозаписей».

## 6. Приватность

- Читаем только: список процессов с аудиосессиями (pid, bundle, флаги in/out). Никакого аудио, экрана, содержимого окон, браузерной истории, сети.
- Заголовки окон — только если пользователь включил и выдал Accessibility/Screen Recording; матчим по маске на лету, не логируем и не храним.
- Никакой отправки наружу; события детекта в логе только как «app=X, start/stop».
- Автостарт записи — только по явному выбору для конкретного приложения.

## 7. Объём работ

| WP | Что | Оценка |
|---|---|---|
| WP-1 | `lowk-audio::activity`: события `MicUse{app,pid,on}` (mac: process objects + listener на `ProcessObjectList`/`IsRunningInput`; win: WASAPI capture-сессии + нотификации), группировка по .app | 3–4 дня |
| WP-2 | Реестр приложений (allow/deny, bundle/exe, названия) и `CallDetector` state machine (чистая, тесты на таймлайнах: ГС, диктовка, mute-flap, два app) в `lowk-session` | 3 дня |
| WP-3 | UI: значок/пилюля/уведомление, конец звонка + саммари, настройки, i18n RU/EN | 3–4 дня |
| WP-4 | Опционально: заголовки окон (Meet/Zoom) через AX / UIA, камера как подтверждение | 2–3 дня |
| WP-5 | Windows: ConsentStore как кросс-проверка, тесты на реальном железе | 2 дня |
| WP-6 | Тест-регрессии в bundle (`qa-bundle`): фейковый процесс с микрофоном, без звука | 1–2 дня |

Итого ≈ 3 недели одним инженером.

## 8. Риски

- Браузерный Meet неотличим от других сайтов без заголовка окна; компромисс — спрашивать «Chrome использует микрофон».
- Process-объекты CoreAudio требуют macOS 14.4+ (совпадает с минимумом тапов); на старых — детект выключен.
- Часть приложений держит mic и в «зале ожидания»/предпросмотре — возможна ранняя пилюля; терпимо, пользователь нажимает.
- Mute в приложении может освободить устройство → ложный «конец»; закрыт 8 с debounce + подтверждение пользователем, автостоп по умолчанию выключен.
- Уведомление на демонстрации экрана выдаёт Lowk; решено «тихим» режимом по умолчанию.
- Подпись/TCC: детект не требует разрешений; заголовки окон — требуют, поэтому опционально.
- Windows: упакованные (Store) и не упакованные приложения в ConsentStore лежат в разных ветках; WASAPI-путь основной.

## 9. Прототип

`swiftc -O spikes/call-detect/main.swift -o call-detect && ./call-detect` — печатает приложения с mic/out и переходы (`+`, `~`, `-`). Проверено на macOS 27 без звука: фиктивный процесс открыл микрофон на 4 с (AVAudioEngine tap) — переходы `+`/`-` появились в пределах интервала опроса 0.5 с; у CLI-процесса bundle id пуст (для приложений приходит bundle). `--once` печатает мгновенный снимок.
