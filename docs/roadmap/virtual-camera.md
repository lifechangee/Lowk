# Зацикленная виртуальная камера («Зацикленная камера»)

Статус: дизайн-ресёрч, 2026-10-22. Приоритет по BRIEF §4 - последний. Прототип перехода: `spikes/virtual-camera/lag.rs`.

Пометки: [известно] - из документации/опыта; [проверить] - не подтверждено под macOS 26/27 и Windows 11 25H2, проверять на тестовом железе до старта работ. Веб-проверку актуальных правил Apple в этой сессии не делал - всё про подпись ниже помечено как требующее подтверждения.

## 1. Что строим

Lowk регистрируется в системе как камера «Lowk Camera». Приложение для созвона (Zoom/Meet/Teams) выбирает её как обычную. Режимы:
1. **Live** - прозрачная передача кадров реальной камеры (по умолчанию, чтобы камера не ломала созвон).
2. **Loop** - зацикленный клип (записанный 1/3/5 мин или импортированный файл).
3. **Transition** - возврат Loop -> Live с эффектом «сетевого лага»: пикселизация, плавно (1.5-3 с) становящаяся резкой, иногда с «заиканием» (повтор кадра 100-300 мс). Обратный переход Live -> Loop - то же самое наоборот (резкость падает, потом подмена).
Микрофон не трогаем (BRIEF): звук идёт прямо из реального микрофона, виртуального аудиоустройства нет.

Управление: бинд/кнопка в оверлее и главном окне; статус виден всегда (см. §7).

## 2. Общая архитектура

```
реальная камера --> [Lowk app: захват] --> кадры --> [Camera Extension / MF-источник / DShow-фильтр]
                           |                                   ^
                    запись клипа (HEVC/H.264 .mov/.mp4)        | читает клип сам (Loop) или принимает кадры (Live)
```
Новый крейт `lowk-vcam` (логика: клип, петля, кроссфейд, лаг-эффект, state machine - чистый Rust, тестируется на Linux CI) + платформенные «надстройки»:
- `platform/macos/LowkCameraExtension` (Swift, отдельный target в app bundle),
- `platform/windows/lowk-vcam-source` (Rust `windows` крейт, COM-DLL).
Зависимости - по правилам ARCHITECTURE §1.2: `lowk-vcam` зависит только от `lowk-types`; `lowk-session` вызывает через trait `VirtualCamera`.

Решение по IPC: **Loop-режим не требует передачи кадров от приложения** - расширение само декодирует клип из общего каталога (App Group на macOS, `%ProgramData%`/`%LOCALAPPDATA%` на Windows) и крутит его. Live-режим требует потока кадров реальной камеры в расширение (шаринг через sink stream / shared memory). Первый релиз можно сделать **только Loop + Transition в/из Live через сам же захват камеры внутри расширения** (расширение открывает реальную камеру напрямую, если не нужно накладывать UI Lowk). Это резко снижает объём IPC.

## 3. macOS

### 3.1 API
- **CoreMediaIO Camera Extension** (`CMIOExtension*`, macOS 12.3+; sink stream, позволяющий приложению подавать кадры в расширение - macOS 13+) [известно]. Старые DAL-плагины (`/Library/CoreMediaIO/Plug-Ins/DAL`) мертвы: Apple убрала их поддержку (Apple Silicon/macOS 14+ не грузит большинство клиентов) - не рассматривать [известно].
- Расширение - отдельный бинарь `*.systemextension` внутри `Lowk.app/Contents/Library/SystemExtensions/`, Swift/ObjC, `CMIOExtensionProvider` -> `CMIOExtensionDevice` -> `CMIOExtensionStream` (source). Кадры - `CMSampleBuffer` из `CVPixelBuffer`/`IOSurface`.
- Установка из приложения: `SystemExtensions.framework`, `OSSystemExtensionRequest.activationRequest(forExtensionWithIdentifier:queue:)`; пользователь одобряет в **Системные настройки -> Основные -> Расширения для входа и расширения (Login Items & Extensions) -> Camera Extensions**; после установки расширение видно приложениям [известно; точные названия пунктов меню на macOS 27 проверить].
- Расширение живёт в песочнице под отдельным пользователем (`_cmiodalassistants`), читать файлы пользователя напрямую нельзя: клип класть в **App Group container** (`group.<teamID>.lowk`), там же JSON с командами (или Mach service / `CMIOExtensionPropertyState` для управления режимом) [известно].
- Реальная камера внутри расширения: у расширения свой TCC-запрос на Camera; проще - приложение захватывает реальную камеру (AVCaptureSession) и подаёт кадры через **sink stream** [проверить стабильность sink на 26/27].
- Чтобы кадры не копировались: `IOSurface`-backed `CVPixelBuffer`, формат 420v/BGRA.
- Декодирование клипа в расширении: `AVAssetReader` + `VideoToolbox`; клип 5 мин 1080p30 в HEVC ~100-200 МБ при 5-10 Мбит/с - хранить, не держать в памяти; для петли держать ring из последних ~2 с декодированных кадров.

### 3.2 Подпись и распространение (главный риск)
- Camera/System extension **нельзя** загрузить в обычном ad-hoc-подписанном приложении: нужен entitlement `com.apple.developer.system-extension.install` у хост-приложения и Team ID; расширение подписывается тем же Team ID. Distribution: **Developer ID Application + нотаризация** (вне App Store) либо Mac App Store. Нужен платный Apple Developer Program (99 USD/год) [известно].
- Entitlement `system-extension.install` - capability, привязана к provisioning profile (App ID с включённым System Extension). Для Developer ID нужен profile типа «Developer ID» [известно].
- **Developer mode без платного аккаунта**: `systemextensionsctl developer on` (после выключения SIP/`amfi` режимов? - уточнить) разрешает загружать расширения вне /Applications и без нотаризации, но всё равно с валидной подписью и profile; бесплатный Personal Team profile, как правило, не содержит `system-extension.install` [проверить на macOS 27]. Ad-hoc-подпись + SIP off + `amfi_get_out_of_my_way=1` технически работает для личного теста, но это модификация системной безопасности: **не рекомендуем и не предлагаем пользователям**.
- **Обходы без платного аккаунта** (честно): (а) нет рабочего пути для обычного пользователя; (б) «мост» через OBS: Lowk экспортирует клип/поток, пользователь сам ставит OBS (его Virtual Camera подписана) и подаёт Lowk-источник (Media Source / NDI / Syphon-подобное) - работает, но UX грубый; (в) open-source камера-расширения других проектов (OBS, Camo Studio - подписаны их владельцами) - только интеграция, не встраивание.
- Нотаризация: `notarytool`, hardened runtime, `xcrun stapler`. CI: сертификат Developer ID в GitHub Secrets (ARCHITECTURE §12 про updater/подпись согласовать).
- После обновления app расширение обновляется заменой - снова может потребоваться одобрение/перезапуск процессов камеры [проверить]. Удаление: `OSSystemExtensionRequest.deactivationRequest`; обязательно добавить пункт «Удалить виртуальную камеру» в настройки (не оставлять мусор).
- Совместимость с клиентами: Zoom/Teams/Meet в Chrome/Safari видят Camera Extensions; некоторые приложения с Hardened Runtime без `com.apple.security.cs.disable-library-validation` могут не видеть DAL, но Camera Extensions работают [известно]. Проверить матрицу: Zoom, Teams, Meet(Chrome/Safari), Telegram, Discord, Slack, FaceTime (последний не нужен).
- Sequoia+ прячет индикатор камеры иначе; зелёная точка горит, пока кто-то читает **реальную** камеру - см. §7.

## 4. Windows

| | Windows 11 22000+ | Windows 10 |
|---|---|---|
| API | `MFCreateVirtualCamera` (mfsensorgroup.h, Frame Server) [известно] | DirectShow Source Filter (`CSource`/`CSourceStream`, DLL + `regsvr32`) |
| Видят приложения | современные (Zoom, Teams, Meet в Chrome/Edge, Camera app) | старые и современные; UWP-приложения часто не видят |
| Права | `MFVirtualCameraLifetime_Session` - без админа, пропадает при закрытии приложения; `_System` + `MFVirtualCameraAccess_AllUsers` - админ | регистрация COM в HKLM - админ; HKCU работает не во всех клиентах |
| Реализация | COM-класс `IMFMediaSource` (+ `IMFMediaStream`, `IMFSampleAllocatorControl`), CLSID активатора регистрируется; DLL грузится в `svchost` Frame Server | DLL x64 **и** x86 (многие Zoom/Teams x86/x64 разные) |
| Подпись | Authenticode желателен; без подписи работает, но SmartScreen/AV шумят | то же; unsigned COM-DLL в HKLM - частый триггер AV |

- Рекомендуемый порядок: сначала Win11 (MFCreateVirtualCamera, session lifetime - не требует админа и инсталлятора), Win10 как отдельный пакет работ. Win10 EOL (октябрь 2025) уже прошёл; решение «поддерживать ли Win10 для камеры вообще» - вопрос владельцу (BRIEF: Win10 - только полное звуковое захват для аудио).
- Кадры: расширение читает общий файл клипа (Media Foundation `IMFSourceReader` в процессе источника) - но Frame Server работает под другим пользователем: клип класть в `%ProgramData%\Lowk\vcam\` (ACL: чтение Local Service) [проверить]. Для Live - shared memory/named pipe от приложения.
- Подпись кода для Windows - необязательна для работы, но обязательна для приличных репутации/SmartScreen: OV/EV сертификат либо Azure Trusted Signing (цена и доступность для физлица-резидента РФ - вопрос владельцу).
- Сторонний путь: OBS Virtual Camera (DirectShow) как внешний мост - как на macOS.

## 5. Видео-часть: бесшовность петли

Принцип: зритель не должен заметить цикл. Приёмы (в порядке ценности):
1. **Запись с учётом петли.** Во время записи показывать пользователю «призрак» первого кадра (наложение 20-30% прозрачности) и подсказку «вернитесь в позу начала»; сигналом о завершении - автоматически выбрать точку конца, где поза близка к началу.
2. **Автоподбор точки склейки.** Для всех пар кадров (i в начале, j в конце, окно +-3 с) считаем расстояние (даунскейл 32x18 grayscale + лёгкий блюр, L2/SSIM) и берём минимум; опционально учитывать положение лица (Vision `VNDetectFaceLandmarks` / `MediaPipe`) и открытость глаз (не склеивать на моргании).
3. **Кроссфейд в точке цикла.** 300-500 мс наложения хвоста на голову (альфа-линейно, лучше с оптическим выравниванием по лицу); для неподвижной позы заметно лучше, чем жёсткий cut.
4. **Пинг-понг** (вперёд-назад) - только если плох маятник движения; на речи/мимике выглядит неестественно - отключен по умолчанию.
5. **Микро-вариативность:** лёгкий шум яркости +-0.5%, случайный сдвиг склейки (точка меняется от цикла к циклу), чтобы не было идеальной периодичности «ровно 3:00». Для 1-мин клипа цикл виден быстро - рекомендовать 3-5 мин.
6. **Согласование с аудио:** звук настоящий, губы не синхронны - рекомендовать клип «слушаю, киваю, молчу» (без речи); для записи подсказать сценарий.
7. **Параметры:** разрешение/кадровая частота = как у реальной камеры (читаем `AVCaptureDevice.activeFormat`/MF media type), иначе клиент переключит режим и будет заметный «скачок»; цветовой профиль = как у камеры; дрожание/шум сенсора можно добавить.
8. Освещение на записи и в момент использования расходится (окно, день/ночь) - предупреждать в UI.

### 5.1 Эффект «сетевой лаг» (Loop <-> Live)
Прототип `spikes/virtual-camera/lag.rs`: блок усредняется и растягивается, размер блока `48^(1-t)` -> 1 (линейно в логарифмической шкале = визуально ровное восстановление). Для продакшена: длительность 1.5-3 с (настраиваемо), Metal/ Direct3D-шейдер (downscale -> nearest upscale), добавить: (а) 1-2 «замёрзших» кадра на старте, (б) блочные артефакты/ослабление цветности (имитация низкого битрейта), (в) случайные дропы кадров в первой трети, (г) рассинхрон момента подмены внутри самого сильного пикселизованного кадра (под ним происходит подмена источника - стык не виден). Эффект не должен длиться долго: «лаг» дольше 4 с выглядит искусственно.

## 7. Этика, злоупотребления, пользовательский контроль

Функция по своей сути - подмена видеопотока собеседникам; может использоваться для обмана (имитация присутствия, обход proctoring/верификации личности/KYC, дезинформация). Риски: нарушение правил площадок и работодателей, мошенничество, репутационный и юридический риск проекта. Предлагаемая модель «пользователь контролирует и осознаёт»:
- Включение только явное, по действию пользователя; никаких автозапусков камеры/автоподмены («автодетект созвона» не включает петлю, только предлагает).
- Всегда видимый индикатор в трее/оверлее (оверлей скрыт от демонстрации экрана, но индикатор камеры - в главном окне/меню-баре; вопрос владельцу, см. ниже) и звуковое/хаптическое подтверждение включения; вернуть Live - один клик/бинд, «паническая» кнопка = мгновенный возврат в Live без эффекта.
- Первый запуск функции: предупреждение о правилах площадок, законности и о том, что запрещено использовать для верификации личности/экзаменов/проктинга; галка «понимаю» с записью даты в локальный журнал.
- Камера в списке именуется нейтрально, но **не маскируется** под реальный бренд устройства; в метаданных устройства есть строка «Lowk Camera» (технический идентификатор не скрываем - согласуется с принципом stealth.md §5: не обходить средства безопасности).
- Никакой подделки лица/генерации (deepfake, ИИ-ресинтез речи) - только запись самого пользователя и его же клип. Клип хранится локально, в vault не синхронизируется по умолчанию, шифрование - вместе с общим пунктом шифрования.
- Не реализовывать обход детекторов «виртуальной камеры» (подмена vendor/product id под реальную камеру) - это уже явный инструмент обмана. [Решение владельца - см. вопросы.]

## 8. Риски
- Подпись/аккаунт Apple (стоимость, регион владельца, проверка личности Apple), сроки одобрения entitlement.
- Хрупкость системных расширений между релизами macOS (особенно 26/27): регрессии sink stream, одобрение после обновления.
- Антивирусы на Windows (регистрация COM, DLL в Frame Server); блокировка корпоративными политиками - на рабочих машинах расширение камеры, скорее всего, запрещено IT.
- Детекторы виртуальной камеры в Zoom/Teams (по имени/ID) - возможное несоответствие ожиданиям владельца; мы это не обходим.
- Нагрузка: декодирование клипа + эффект + захват реальной камеры; целевая нагрузка <5% CPU на M4 (HW-декодер).
- Юридический риск функции в целом (см. §7).
