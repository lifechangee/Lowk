# Слайды / снимки трансляции — исследование и дизайн

Статус: роадмап (после M2). Основа: BRIEF §6 и решения раунда 2, `docs/research/llm-and-jev.md` (B1–B6), `crates/lowk-capture`. Прототип пре-фильтра: `spikes/slides/`.

## 1. Что строим
Во время созвона Lowk сам сохраняет снимок, когда на демонстрации сменился слайд или на нём появилось новое содержимое (в т.ч. дописка при 90%+ совпадении кадра), плюс ручной снимок по бинду. Снимки вставляются в `.md` созвона и доступны в Ask/саммари. Захват — только окно/область приложения созвона.

## 2. Источник захвата
- **macOS**: ScreenCaptureKit, `SCContentFilter(desktopIndependentWindow:)` для окна приложения созвона. Проблема: у Zoom демонстрация идёт в отдельном окне, у браузерных созвонов — вкладка внутри окна браузера. Поэтому: (а) авто-выбор окна по bundle id «приложения созвона» из настроек (тот же выбор, что для звука), кандидат — самое большое окно приложения; (б) ручной выбор области внутри окна («Выбрать область демонстрации», запоминается на созвон) — обязательный запасной путь. YouTube в соседнем окне не попадает вообще: фильтр по окну, а не по экрану. Окна Lowk исключены (`exclude_windows`, уже есть в `grab_region`).
- **Windows**: Windows Graphics Capture по HWND (`GraphicsCaptureItem::CreateFromWindow`), Win10 1903+; рамку захвата на Win10 проверить (не должна попадать в трансляцию). Для браузерных созвонов — та же область внутри окна.
- Права: Screen Recording (TCC) на macOS уже нужны скриншотам.
- Окно свёрнуто: SCK его не отдаёт — пауза детектора и пометка в UI; перекрытое окно отдаётся нормально.

## 3. Частота и обработка кадра
1 fps в покое (0.5 fps после 30 с без изменений), всплеск 3 fps на 3 с после срабатывания (сборки слайда). Поток запрашиваем уменьшенным, для анализа — gray 384x224 (area-average + blur σ=1). Полный кадр (≤1568 px по длинной стороне) берём только при срабатывании. CPU: доли мс–единицы мс на кадр, GPU не нужен.

## 4. Локальный детектор (этап 1, recall-first)
Сравниваем с **последним сохранённым** снимком S (не с предыдущим кадром — иначе медленные эффекты ускользают) и с кадром t-1 (стабильность). Сетка 24x14, ячейка 16 px анализа.
- Ячейка «изменилась»: средняя абс. разница > 6/255 (T_CELL).
- «Видео/webcam» ячейки: меняются кадр-к-кадру ≥4 подряд → в маску на 8 с + кольцо в 1 ячейку (края видео «протекают»). Решения по маске не принимаются.
- «Движущиеся» ячейки (курсор, шум) исключаются; кадр «стабилен», если их ≤3; нужно 2 стабильных кадра подряд (≈2 с) — это и debounce анимаций.
- Кандидат «дописка»: связная область (8-связность) из **≥2 ячеек** (~0.6% площади ≈ слово/строка), не касающаяся внешнего ряда ячеек (тосты, баннеры «вы демонстрируете»). Верхней границы нет — 99% совпадения проходит.
- «Новый слайд»: изменено ≥25% ячеек (или pHash 32x32 Hamming ≥12/64). Глобальный SSIM/pHash как основной критерий не годится: дописка меняет <5% пикселей.
- Cooldown 3 с (кроме «нового слайда»); страховочный проход раз в 20–30 с с порогами вдвое чувствительнее; периодический снимок раз в 2 мин (настройка, по умолчанию выкл).
- Скролл документа: срабатывает один раз по остановке; непрерывный скролл гасится маской.

### Результаты прототипа (`spikes/slides/RESULTS.txt`, 10 seed × 5 событий)
| Конфиг | recall | precision | FP |
|---|---|---|---|
| по умолчанию | 100% | 100% | 0 |
| шум 4 вместо 2 | 100% | 100% | 0 |
| MIN_CELLS=1 | 100% | 71% | 20 (курсор/мелочь) |
| T_CELL=3 | 100% | 96% | 2 |
| T_CELL=10 | 100% | 100% | 0 |

Событий: 30 новых слайдов, 10 «+1 буллет», 10 «+слово». Оговорки: синтетика лёгкая; маска видео в ней почти не влияет (отключение не ухудшило — видео ловится правилом «≤3 движущихся ячеек»); нужен реальный корпус (~10 записей). Вывод: минимум 2 ячейки обязателен (убирает курсор), одиночная ячейка — главный источник FP. Jev на синтетике не гонялся: ключа TypeSafe у владельца пока нет.

## 5. Когда спрашиваем Jev (этап 2)
Только по кандидатам этапа 1 (несколько вызовов в минуту на активной демонстрации, 0 в покое), после локального дедупа pHash/текст-хэш.
Актуальные данные (docs.typesafe.ai, проверено 2026-10-22): модели `jev-1.13.0`, `jev-1.14.0` (с 14.10.2026), вход **$0.042 / 1M токенов, выход бесплатно**. Картинки: PNG/JPEG, сторона 280–1568, всего 78 400–2 458 624 px, ≤16 МиБ на файл, тело ≤32 МиБ, нужен заголовок `TypeSafe-Danger-Zone-Images: true` (иначе 400); считаются обычными входными токенами, оценка токенов «скоро» (число неизвестно). Расхождение: страница моделей пишет «Jev accepts text only», страница images картинки принимает — считаем функцию экспериментальной, «хуже текста» (блог 1.14). Лимиты — на организацию, 429 → ретрай с `retry-after`. Алиасы плавают — пинить `jev-1.14.0`.

Запрос: `POST https://api.typesafe.ai/v1/systemone`, Bearer-ключ пользователя (BYOK):
```json
{"model":"jev-1.14.0",
 "state":"Image old = previously saved slide. Image new = current frame. Image diff = crop of the changed region in new.",
 "assets":{"old":{"type":"image","format":"jpg","data_base64":"…"},"new":{},"diff":{}},
 "questions":{
  "new_slide":{"type":"noul","instructions":"Is image `new` a different slide than `old` (other title, topic or layout)?"},
  "content_added":{"type":"noul","instructions":"Does `new` contain new text, a bullet, number, figure or code that `old` lacks?"},
  "only_chrome":{"type":"noul","instructions":"Are the differences only a mouse cursor, a video participant, a notification or a progress indicator?"}}}
```
Ссылки на картинки — в `state` (одна копия на запрос). Размер: 1024x576 JPEG q80 ×2 + кроп ≥280 px. Стоимость (оценка, если картинка ≈1–3k токенов): запрос ≈ 3–9k токенов ≈ **$0.0001–0.0004**; 12 вызовов/мин × 3 ч ≈ 2 160 вызовов ≈ **$0.2–0.8**. Задержка заявлена 70–500 мс (из США, самоотчёт) — мерить из РФ/ЕС.
Решение: сохранить, если `new_slide>0.5` ИЛИ (`content_added>0.6` И `only_chrome<0.5`); неуверенность (0.3–0.7) → **сохранять** (лишний снимок дешевле пропущенного). Ошибка/429/таймаут >1.5 с → сохранить с пометкой «не проверено». Не просить Jev считать пункты/даты.
Интерфейс `SlideVerifier` (trait): `Jev`, `VisionLlm` (OpenRouter, max_tokens 3), `LocalOcr` (Apple Vision / Windows OCR по кропу bbox двух кадров, diff строк), `None`. Jev — не жёсткая зависимость.

## 6. Видео, анимации, курсор, скролл
- Видео в слайде / webcam-плитки: в маске (§4); снимок по изменениям вне маски. Если весь слайд — видео, детектор молчит; остаются ручной и периодический снимки.
- Курсор/указка: движущийся блоб <2 ячеек не кандидат. Оверлей Lowk в кадр не попадает.
- Анимации/переходы: ждём стабильности (2 кадра), потолок ожидания 4 с.
- Скролл/зум: один снимок по остановке; cooldown 3 с.
- Тосты/баннеры/индикатор говорящего: внешний ряд ячеек игнорируется; зоны-исключения настраиваются.

## 7. Хранение и дедуп
Файлы: `<vault>/<папка>/assets/<call-id>/slide-0007-00-12-34.jpg` (JPEG q85, ≤1568 px; PNG для кода/мелкого текста — опция). Событие в журнал `.lowk/state/live/<id>.jsonl`: `{t, kind: slide|addition|manual, path, verified: jev|local|none, p_new, bbox, sha, phash}`. В `.md` — блок в позиции по времени среди реплик: `![[assets/…jpg]]` + callout `lowk-image` с подписью/OCR (подпись индексируется, как для скриншотов). Дедуп: pHash + сравнение OCR-текста с уже сохранёнными (возврат на прошлый слайд не дублируем). Лимит ≤500 снимков/созвон, ~150–300 КБ каждый ⇒ ≤150 МБ худший случай; при превышении — только «новые слайды».
Контекст LLM: подпись/OCR идёт в ledger текстом; картинка прикладывается в Ask по запросу/для последних 1–2 слайдов, чтобы не раздувать контекст; в саммари — заголовки слайдов + OCR.

## 8. Приватность
- По умолчанию всё локально: этап 1 + LocalOcr. Jev/VisionLlm — **только с явного согласия** и предупреждением «содержимое экрана уйдёт в облако TypeSafe»; в диалоге — что именно отправляется (два кадра и кроп). Без телеметрии.
- Папка «только локально» (флаг облака из настроек `llm`): облачный верификатор принудительно выключен, работает локальная эвристика/OCR, в UI подпись «локально».
- Счётчик в оверлее виден только владельцу (стелс). Ключ TypeSafe — в keychain, не в `.md`.

## 9. UI
- Оверлей: маленький счётчик «▣ 7» у статуса записи (серый), короткая вспышка при новом снимке, без миниатюр; бинд ручного снимка (отдельно от скриншота монитора).
- Страница созвона → вкладка «Скриншоты»: сетка по времени, фильтры «слайды / ручные / непроверенные», удалить, «показать в транскрипте», «Спросить про этот слайд».
- Настройки: источник (приложение/окно/область), режим «локально / локально + Jev / локально + vision LLM», ключ Jev, чувствительность (3 пресета = T_CELL/MIN_CELLS), периодический снимок, зоны-исключения.
- Правовое предупреждение при первом запуске дополнить словом про снимки экрана.

## 11. Риски
1. Jev: ранний доступ, картинки в «danger zone» и «хуже текста», противоречие в документации, только облако, один вендор → trait + локальные варианты; до релиза сравнить на корпусе с 2–3 vision LLM.
2. Браузерные созвоны: окно ≠ демонстрация (вкладки, панели) → ручная область; позже авто-поиск крупнейшего прямоугольника.
3. Синтетика не доказывает качество: сжатие Zoom/Meet, градиенты, тёмные темы, мелкий шрифт на 4K (поднять анализ до 480x270).
4. Запись экрана чужих людей — правовое предупреждение и согласие.
5. Нагрузка/батарея при всплесках 3 fps — мерить на M4 и i5-10400F.
6. Токены на картинку не опубликованы — стоимость оценочная; замерить `usage.input_tokens` на первом ключе.
