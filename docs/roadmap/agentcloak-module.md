# Privacy-модуль («AgentCloak-подобный»): актуализация плана

Статус: 2026-10-22. Исходный ресёрч `docs/research/agentcloak.md` (2026-10-20) - **остаётся актуальным, новых исследований не делали**. Здесь только привязка к текущей архитектуре и реестр отличий.

## 1. Что изменилось/уточнено относительно ресёрча
- Репозиторий уже структурирован как Cargo workspace с `lowk-types` в роли контракта (ARCHITECTURE §1). Модуль должен быть **вне** этого workspace, чтобы переиспользоваться: отдельный репозиторий/каталог `cloak/` со своим `Cargo.toml` (лицензия: Apache-2.0 или MIT для максимального переиспользования; Lowk - AGPL-3.0, зависимость Lowk -> cloak допустима).
- В Lowk единственная точка выхода данных в облако - `lowk-llm` (`ChatClient` + `PromptBuilder`, ARCHITECTURE §5). Интеграция: **один trait `Redactor` в `lowk-types`** (`fn redact(&self, ctx: &PromptParts) -> Redacted`, `fn restore(&self, chunk) -> String`), реализация-адаптер к `cloak`. Крейты друг на друга не зависят (правило §1.2): `lowk-session` подаёт `Redactor` в `lowk-llm`.
- Политика облака у папки (`_folder.md`: cloud policy) уже есть - privacy-модуль применяется только когда папка разрешает облако; для локальной LLM не нужен.
- Скриншоты в контексте (`lowk-capture`) - OCR-закраска bbox, пункт модуля «изображения», делается во вторую очередь.
- Streaming-ответ LLM (SSE через `lowk-llm`) требует re-identification с буфером хвоста - критично совместить с текущим стримингом оверлея (задержка не более 1-2 токенов).

## 2. Раскладка
```
cloak/
 ├─ cloak-core    правила + валидаторы (Luhn, IBAN, ИНН/СНИЛС/ОГРН), vault подстановок (XChaCha20-Poly1305, ключ из keychain), streaming-restore
 ├─ cloak-ner     ONNX (`ort`): GLiNER (Apache-2.0 веса) + Slovnet/Natasha RU; загрузка моделей по требованию (как sidecar-движки Lowk)
 ├─ cloak-image   OCR (Tesseract/Apache-2.0) + закраска bbox
 ├─ cloak-proxy   локальный OpenAI-совместимый HTTP-прокси (axum), CLI `cloak`
 └─ cloak-ffi     C-ABI (для не-Rust проектов)
```
Lowk использует `cloak-core` + `cloak-ner` как библиотеку (не прокси); другие проекты - прокси/CLI.

## 3. Порядок работ (совпадает с research §4, уточнён)
| Этап | Содержание | WP |
|---|---|---|
| C1 | `cloak-core`: правила RU+EN, vault, format-preserving подстановки, streaming-restore, property-тесты | 8-10 |
| C2 | Интеграция в Lowk: `Redactor` trait, переключатель в настройках, визуальный отчёт «что замаскировано» | 3 |
| C3 | `cloak-ner`: GLiNER/Slovnet ONNX, бенчмарк RU/EN (нужен свой размеченный датасет) | 15-20 |
| C4 | `cloak-proxy` + CLI | 5 |
| C5 | `cloak-image` (скриншоты) | 5-8 |
Итого MVP (C1+C2+C4): ~16-18 WP (в ресёрче "2-3 месяца"); качественный (с NER и датасетом): ~35-45 WP.

## 4. Риски и решения без изменений
Лицензии весов (проверить Rampart; GLiNER v1 CC-BY-NC исключить), пропуски NER, обратное восстановление имён моделью по контексту, честная формулировка про 152-ФЗ/GDPR, конкуренция с бесплатным AgentCloak Desktop (ниша - открытый переиспользуемый модуль).
