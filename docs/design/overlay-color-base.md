# Цветовая база адаптивного оверлея (O4)

Код: `crates/lowk-stealth/src/palette.rs` (математика и таблица констант), `tone.rs` (сглаживание, гистерезис, сетка 4x3).
Витрина: [overlay-color-swatches.html](overlay-color-swatches.html) / [.png](overlay-color-swatches.png), числа в [.json](overlay-color-swatches.json).

## Что было не так

Старая логика смотрела на яркость. Цветной палитре (`Color`) нужно было `яркость > 0.056`, поэтому тёмный насыщенный синий
(navy, яркость около 0.016) проваливался в чёрный пресет, а светло-голубой работал. Цвет и яркость были склеены в один порог.

## Конвейер (на каждую из 12 ячеек сетки)

1. Средний цвет ячейки (усреднение в линейном свете) переводится в **OKLab / OKLCH**: `L` (светлота), `C` (насыщенность), `h` (тон).
2. Сглаживание: медиана из 3 последних замеров по каждой компоненте (вспышка в один кадр не двигает цвет).
3. **Полярность** (светлый скрим с тёмным текстом или тёмный скрим с белым) решается по `L` триггером Шмитта.
   Верхний порог растёт с насыщенностью, поэтому красный, зелёный и пурпурный получают тёмный скрим того же тона, а не бледный.
4. **Скрим** сохраняет тон фона, снижает насыщенность и получает светлоту под контраст.
5. **Текст** белый или почти чёрный; приглушённый текст это тот же цвет с альфой из CSS; **акценты** подбираются под скрим.
6. Контраст проверяется по худшему пикселю фона под строкой, WCAG 2.x и APCA.
7. Новый тон уходит в UI только если он заметно отличается (яркость на 0.03, светлота скрима на ΔE 0.02, смена вида).

| Нейтральный фон | OKLCH `C < 0.02`: пресеты (скрим `12,12,15` / `255,255,255`, без оттенка) |
| Порог полярности (нейтральный) | на тёмный текст при `L > 0.60`, обратно при `L < 0.52` (эквивалент старых 0.22 / 0.14 по яркости) |
| Рост порога от насыщенности | до `+0.20` при `C ≥ 0.25` (оба порога) |

Красный, зелёный, бирюзовый, синий, пурпурный не затронуты |
| Тёмный скрим | `L = clamp(0.17 + 0.25 * max(L_фона - 0.15, 0), 0.17, 0.30)`, `C = min(0.6 * C_фона, 0.10)`, тон фона |
| Светлый скрим | `L = clamp(0.95 + 0.04 * (L_фона - 0.70) / 0.30, 0.95, 0.99)`, `C = min(0.25 * C_фона, 0.04)`, тон фона |
| Текст | белый `247,247,249` на тёмном, `10,11,15` на светлом |
| Приглушённый текст | тот же цвет, альфа `0.72 + 0.16 * k` (0.784 при прозрачности 60 %) |
| Ореол текста (`inv`) | тёмный скрим: почти чёрный с тоном фона; светлый: почти белый |
| Акцент «интерактив» | оттенки по порядку 150°, 205°, 100°; светлота ищется шагом 0.02 до WCAG ≥ 4.5 к скриму и ≥ 3 к скриму над худшим фоном |
| Акцент «перемещение» | оттенки 80°, 25°, 330°, то же правило |
| Смена оттенка акцента | если его тон ближе 45° к тону скрима, берётся следующий кандидат (зелёный на зелёном невозможен) |
| Вид `Color` | тёмный скрим с тоном и `C_фона ≥ 0.05` (выход при `< 0.035`) |
| Непрозрачность скрима | `max(0.85 * k, scrim_min, 0.72)`: пол 72 % держит читаемость при любом ползунке |
| Чёрный кадр (0,0,0) | «неизвестно» (нет прав записи экрана): остаётся предыдущий или тёмный пресет |

Пороги проверки (витрина и юнит-тесты): основной текст WCAG ≥ 4.5 и APCA |Lc| ≥ 60, приглушённый WCAG ≥ 3, акценты WCAG ≥ 3.

## Как ведут себя особые случаи

* **Тёмно-синий / navy / королевский / чистый синий**: тёмный скрим синего тона (например navy `#010e42`), белый текст, зелёный акцент. Не чёрный.
* **Красный, фиолетовый, зелёный, бирюзовый, оранжевый**: тёмный скрим того же тона, белый текст (насыщенность поднимает порог).
* **Яркие насыщенные светлые (жёлтый, лайм, золотой, светло-оранжевый, светло-зелёный, ярко-зелёный, светлый циан, розовый), пастельные**: светлый скрим (`L 0.95–0.99`) с оттенком фона (жёлтый `240,220,40` даёт скрим около `251,248,218`, а не тёмно-оливковый `52,47,0`), тёмный текст. Решение владельца. Проверяется юнит-тестами `bright_saturated_colours_get_a_light_tinted_scrim`, `dark_and_mid_saturated_colours_still_get_dark_scrims`, `yellow_polarity_does_not_flicker_on_mid_colours` и `swatches::bright_saturated_backdrops_*`; контраст основного текста WCAG ≥ 7 и APCA ≥ 75, приглушённого и акцентов ≥ 4.
* **Градиенты, код слева и документ справа**: у каждой ячейки свой тон; блок текста берёт ячейку, ближайшую к среднему (`blockTone`), а при расхождении ячеек получает локальный скрим 72 %.
* **Фото и шум, видео с яркими пятнами**: по среднему цвету, контраст проверяется по самому плохому пикселю; пол скрима 72 % закрывает пики.
* **Чистый чёрный / белый**: пресеты.
* **Переходы**: медиана из 3, триггер Шмитта, мёртвая зона; цвет скрима в UI плавно меняется за 0.2 с. Фон, дрожащий около порога, не мигает (тест `colour_transition_has_hysteresis_and_no_flicker`).

## Проверки

* `cargo test -p lowk-stealth`: математика OKLab/APCA, перебор сетки цветов 6x6x6, тёмно-синие, насыщенные, светлые, акценты, гистерезис, шум; `swatches::*` прогоняет 48 фонов через настоящий `AdaptiveTone`, проверяет контраст по пикселям и что `overlay-color-swatches.json` актуален.
* `just test-ui-visual`: `ui/e2e/overlay-colors.spec.ts`: витрина (все карточки «проверено»), настоящий оверлей Svelte над 14 фонами с пиксельным контрастом ≥ 4.5, скриншоты.
* Перегенерация: `UPDATE_SWATCHES=1 cargo test -p lowk-stealth swatches`, затем
  `cargo run -p lowk-stealth --features swatches --example overlay_swatches`, затем `SWATCH_PNG=1 pnpm --dir ui exec playwright test overlay-colors --project=chromium --update-snapshots=missing`.
